## 二、深度维度分析

### 2.1 架构合理性

| 现状 | 问题 | 影响 |
| ------ | ------ | ------ |
| `shell → plugin-llm` 单向依赖，包级无环 | — | 分层骨架成立，可扩展 |
| 11 个插件都实现 `register()` | **无人消费**；`apps/full/src/App.tsx` 手写第二份注册表 | 双真相源，改插件必漂移 |
| `register.order` | 5 组冲突（target/monitor=10、cost/ops=20、marketing/ai=30、prompt/ai-family=40） | 侧边栏顺序不确定 |
| 6 处 `@yyc3/plugin-x/pages/*` 深路径导入 | 包无 `exports`，深路径物理不存在，靠 Vite alias + tsconfig paths 兜底 | 离开 Vite 即失败，无法对外发布 |
| 合并版仅挂 7 系统 | 4 引擎无页面、无路由 | 「4 大业务引擎协同」不可见 |
| token-console 独立 Next.js 16 子工作区 | 与主仓仅经 family 包耦合；`next.config.ts` 为 10 行占位 | 双运行时/双构建成本高 |

### 2.2 代码质量

- 类型：`@ts-ignore` 0 处；`as any` 约 20 处（`routes: [] as any` × 5、`AIAssistantHub` × 4）。
- 复杂度：仅 1 个 >400 行文件（`AIAssistantHub.tsx` 643 行）。
- 重复：9 份 `main.tsx` 完全相同；8 份 `App.tsx` 骨架同构；Mock LLM 文案双份；注册表双份。
- 异常处理：`storage` / `sse` / `router` / `llm-bridge` 均有降级；缺口为 EventBus 回调无隔离、SSE 重连无 `.catch`、`EdictMessage` 裸解析、多处 `catch {}`。
- 注释：文件标头统一；真实缺口以 `// Phase 2` 隐性承载，无 TODO 追踪。

### 2.4 性能风险

- 首屏单 chunk 354 kB（gzip 115 kB）；6 处 `INEFFECTIVE_DYNAMIC_IMPORT` 使王朝模块被静态打包，懒加载失效。
- Tailwind 内联进 HTML（7.87 kB），不可长期缓存，且迫使 CSP 保留 `unsafe-inline`。
- Lighthouse 断言含 `render-blocking-resources ≤ 0` 与 `categories:pwa`（Lighthouse 12 已移除）→ 门禁不稳。
- 无真实数据层，接口瓶颈当前为 0；接入后端后 localStorage 同步读写、无分页/虚拟化是首要风险。
- LLM 直连 Provider（无服务端代理）：受 Provider 限流与 CORS 策略约束，首 Token 延迟不可控。

### 2.6 可维护性

- 部署口径已收敛为「Pages（生产）+ Docker（私有）」两套；安全头仍需在 Nginx 与 Pages 响应头（如启用）两处维护。
- 排障：仅 React `ErrorBoundary`；`SENTRY_DSN`/`POSTHOG_KEY` 未接线；无全局 `unhandledrejection`、无结构化日志。

- 二次开发：新增插件需同时改 `vite.config.ts` alias、`tsconfig` paths、`App.tsx` 注册表三处，成本高于文档承诺。

### 3.3 边界与异常清单

1. 输入：空/超长提示词、`maxTokens` 越界与负值。
2. 数值：营收 0/负值/极大值、浮点精度（`toFixed(2)`）。
3. 时间：跨年、闰月农历、DST 与非 UTC+8 时区（`lunar-engine.ts` 依赖本地时区）。
4. 存储：配额写满、隐私模式禁用、无 `window` 环境。
5. 网络：Provider 429/500/超时/断流、SSE abort、重连风暴。
6. 并发：多 Tab 写同名 Key、同页多 Hub 实例。
7. 浏览器：Safari 无 `webkitSpeechRecognition` 降级、iOS 安全区。
8. 部署：项目子路径、非 root 容器低端口（K8s）、严格 CSP 无 `unsafe-eval`。

**P2 一般**：EventBus 无隔离；SSE 重连无 catch；裸 JSON 解析；静默吞异常；引擎除零/负值/敏感度公式错误；农历时区依赖；深路径导入与无 `exports`；9 份 `main.tsx` 复制；无 `type: module`；Docker heredoc/低端口；无 Sentry/全局兜底；覆盖率无阈值。

**P3 优化**：文档命名规范、README 排版、手写徽章、无 CHANGELOG、无 Prettier、孤儿 `styles.css`/`tsconfig.base.json`。

### 4.3 优化排期

| 周期 | 动作 |
| ------ | ------ |
| 短期（已完成） | P0 全关闭；发布链路重建；文档门禁修复；依赖安全清零 |
| 中期（2–3 周） | ESLint/Prettier 落地；8 App 补 tsconfig；覆盖率阈值；注册表单一真相源；E2E 改跑产物；token-console 纳入或移出 CI |
| 长期（1–2 月） | 4 引擎最小页面；包 `exports/files`；插件脚手架；Sentry + 全局错误兜底；安全头单一模板生成 |

### 4.4 可行性与风险

- **技术可行性：高**。纯静态 SPA，无数据库与中间件，容器与 Pages 均可发布，回滚成本低。
- **交付可行性：中**。P0 已清，但业务价值仍受「引擎无 UI」制约，需产品确认 Phase 4 边界。
- **主要风险**：单点维护（bus factor = 1）；token-console 未纳入 CI 的隐性腐化；CSP 无法收紧导致的 XSS 缓解不足。

### 5.3 协作卡点

2. 历史 CI 长期红导致红灯脱敏 → 先修必红项，再逐步收紧。
3. 空洞门禁（`lint`/`build` 为 echo）→ 补齐或删除，禁止假绿。
4. 环境要求三处不一致（README/Dockerfile/CI）→ 以 `packageManager` + `.nvmrc` 为单一真相源。
5. E2E 与产物脱节 → 改为 `vite preview` 或静态服务器指向 `dist`。
