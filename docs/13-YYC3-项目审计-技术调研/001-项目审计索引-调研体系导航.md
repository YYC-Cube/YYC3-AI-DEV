## 三、同步契约（强制）

1. **变更即记账**：任何影响构建、测试、部署、安全的改动，必须在 003 追加一行，写清「改了什么 / 为什么 / 怎么验 / 结果」。
2. **报告随台账滚动**：003 中标记为「已验证」的条目，若改变了现状判断（如漏洞清零、覆盖率变化），必须同步修订 002 对应章节，并在两文「变更历史」登记。
3. **数字只写实测值**：报告中的测试数、覆盖率、漏洞数，必须是可在本地或 CI 复现的命令输出；不得沿用历史快照。
4. **历史段落不改写**：里程碑类历史记录保留原貌，口径变更以「变更说明」形式追加（示例见 `docs/YYC3-生产部署-就绪规划.md` 的部署口径变更注记）。
5. **失效即删除**：文档描述与代码不一致时，优先删改文档；确需保留的历史背景，移入 `docs/archive/`。
